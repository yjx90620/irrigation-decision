# 灌溉决策项目：审计问题修复计划

## 背景（Context）

用户把这个项目的公开仓库交给 ChatGPT 做交叉验证，ChatGPT 给出了一份很长的审计意见，列出了一批 P0（阻断性）和 P1 问题。用户要求先逐条核实审计意见的真实性，只有确认属实的才修，且修复优先于继续训练/生成结果——哪怕要中断当前在跑的任务、哪怕已经花了很长时间训练。

**我已经用当前代码 + 实际数据逐条核实了审计里的大部分 P0 声称，结论是：这份审计基本准确，不是幻觉。** 已核实的问题清单和证据见下。因为问题集中在 `rotation.py`（轮作引擎，几乎被所有下游脚本调用）和 `rotation_env.py`（RL 环境），今天生成的"系统升级"阶段结果——跨季优化、α扫描、边际水价值、算法对比、RL 训练（包括论文二刚写完的核心对比结果）——的有效性现在都存疑，需要在重新生成前把根源问题修掉。

我已经停止了当前后台在跑的对比1b任务（3+1个站点的跨季优化搜索），并把之前对比1的备份文件都还原了，避免在有问题的基础上继续产出更多结果。

用户已经就 P0-1 的修复方向做了选择：**方案A——重新率定小麦品种参数，确保所有纳入实验的年份小麦收获都早于玉米固定播种日 06-15**，不改变现有"固定播期+跨季耦合"的研究框架。

### 阶段 1：P0-1 轮作日历（方案A：重新率定小麦品种）

**目标**：对全部5个站点、全部会用到的历史年份，小麦模拟结束（`model_is_finished`触发的实际日期）严格早于 `MAIZE_PLANTING`（06-15）。

**做法**：
1. 写一个诊断脚本（复用 `run_rotation_years_independent` 的单年独立评估逻辑），对每个双季站点、1982-2025 全部年份，跑一次充分灌溉（不受配额约束的场景），记录小麦实际收获日期，找出当前 `wheat_params_for()` 参数下哪些年份晚于06-15。
2. 参照 `cropping_systems.py` 里已有的"Beijing 用 Maturity=2000 短生育期品种"先例，对每个站点分别下调 Maturity/Senescence/HIstart，直到诊断结果显示所有年份都留有安全边际（不只是卡在06-15边界，留几天缓冲应对未来可能纳入的新年份）。
3. 在 `rotation.py`/`rotation_env.py` 里加一道硬断言：`run_season`/`_start_season` 返回结果后检查 `harvest_date <= MAIZE_PLANTING 前一天`，不满足就 `raise RotationCalendarError`，不静默继续。
4. 新增测试文件 `src/sim/test_rotation_calendar.py`：
   - `test_wheat_harvest_precedes_maize_planting`：对全部站点全部年份跑一遍，断言不抛异常
   - `test_dates_are_strictly_monotonic`：检查 `run_rotation_series` 多年连续场景下年份之间日期不倒退
   - `test_no_unmodelled_days_between_seasons`：小麦收获日到玉米播种日之间的间隔天数，记录下来但不强制为0（因为方案A本来就允许有几天缓冲），只断言间隔非负
5. `run_season`/`run_rotation_year` 增加返回值：实际播种/收获日期、空档天数、交接前后 `th`（土壤储水量）——供测试和日志使用，不改变现有产量/灌溉量字段。

**受影响但只需重新跑、不需要改代码的下游**：`optimize_cross_season.py`、`scan_allocation.py`、`marginal_water_value.py`、`optimize_algorithm_comparison.py`、`task_sensitivity.py`、RL 训练——这些都是纯调用方，日历修好后直接重新生成结果即可。

### 阶段 2：P0-2 年度配额硬约束

修改 `rotation_env.py` 的 `safety_filter()`：
- 保留临界亏缺补水的意图，但改成 `applied = min(requested_or_safety_action, max(remaining_quota, 0.0))`，不再突破配额。
- 补水量不够时的处理：记录 `quota_violation_mm`（这种情况下应为0，因为不再允许超配额），改为把这一步标记为 `emergency_shortfall` 并施加一个明确的欠水惩罚项，而不是凭空多给水。
- `step()` 里新增字段并写入 `info`：`raw_action_mm`（已有）、`filtered_action_mm`、`actual_model_irrigation_mm`、`quota_used_mm`、`quota_violation_mm`、`safety_rule_triggered`。
- 断言：`assert quota_used_mm <= annual_quota_mm + 1e-6`。
- 单元测试：构造一个人为的"持续零灌溉必然导致临界亏缺"的场景，验证 episode 结束时用水量不超配额。

### 阶段 3：P0-4 采样与奖励结构

**站点采样**：`RotationGymEnv` 改成接受 worker rank，按 `site = SITES_ORDER[rank % len(SITES_ORDER)]` 固定站点，年份/土壤/偏好仍随机。`train_rotation_compare.py` 的 `make_direct_env`/`make_residual_env` 工厂函数改为接受 rank 参数（`SubprocVecEnv` 的 `env_fns` 本来就是按 index 构造的，用 `functools.partial` 传 rank 进去，Windows spawn 安全，train_rotation_utils.py 已经在用这个模式）。训练日志新增每站点 episode/transition 计数汇报。

**奖励结构**：改成每个轮作年只在系统级终点给一次终端产量奖励（双季：小麦+玉米都收获后一次性算；单季：收获后一次性算），稠密的 `tr_ratio` 项降权为小比例 shaping（具体比例作为超参数，先给一个不改变最优策略排序的小系数，如 dense项总和的量级控制在终端项的 10%-20% 左右，训练时可调）。

**评估指标**：`evaluate()` 同时报告 `undiscounted_return` 和 `discounted_return`（gamma=0.995），不再把未折扣和单独称为"scalar_return"。

### 阶段 4：P0-5 Residual 设计

- 把离散 `RESIDUAL_DELTAS` 改成连续残差动作（`spaces.Box`），或者至少把离散候选值改成不会在 base∈{0,20} 时产生重复裁剪结果的集合。
- 去掉"by construction 从规则策略开始"这个文档表述，除非真的做显式零残差初始化（policy 最后一层 bias 置零/小学习率热身），否则如实描述成"初始策略在规则动作附近做随机扰动"。
- direct/residual 使用相同的场景种子序列（配合 P0-6b 的 seed 修复）、至少3个独立 seed 各跑一次，报告学习曲线不只是最终模型。
- 补充基线：至少加一个"预留小麦/玉米配额"的规则基线（比如按阶段边际水价值分析结果设一个固定 60/40 或按站点 best-fixed-alpha 分配的规则），不能只对比一个已知会把配额耗在小麦上的弱规则。

### 阶段 5：P0-6 归一化与随机种子

- `leave_one_out_rotation.py`：`ft_model, ft_vecnorm = train_rotation_policy(...)`，`load_policy(ft_model, ft_vecnorm, "residual")`。加一个断言/测试确认加载的 vecnorm 文件名和模型是同一次训练产出的。
- `gym_env.py`/`residual_gym_env.py` 的 `reset()`：
  ```python
  super().reset(seed=seed)
  if seed is not None:
      self._rng.seed(seed)
  ```
- 新增测试：同一个 seed 连续 reset 两次（中间不传 seed）应该继续推进随机序列而不是重复；两次用相同 seed 构造全新环境应该得到完全相同的站点/年份/偏好/动作轨迹。

### 阶段 6：P1（P0 全部验收通过后）

按审计原文顺序处理：指纹/风险预测协议按站点实际种植制度重建 + 时间切分不与测试期重叠；CMIP6 delta 改成"先各模式算差值再集合平均"，未来 ET0 接入已下载的辐射/风/湿度模式信号，海拔改用各站点真实值；超体积参考点用归一化+固定参考点方案；断点续跑逻辑统一成 manifest（experiment/site/soil/year range/condition/algorithm/seed/config hash/status/failure reason），`.venv/Scripts/python.exe` 硬编码路径全部替换成 `sys.executable`。

### 验收清单（P0 全部通过才允许重新训练/生成正式结果）

对照审计原文第四节的12条，逐条建自动化测试：
1. 日历严格单调（阶段1的测试）
2. 无"未来状态传给过去"（阶段1的断言+测试）
3. 作物间/跨年空档被模拟或明确重置（阶段1，方案A下空档应该稳定为正且很小）
4. 任意轨迹总灌溉量不超年度硬配额（阶段2的断言+测试）
5. 同一 seed 完全复现环境轨迹（阶段5的测试）
6. 各站点训练 transition 数符合预设采样比例（阶段3的训练日志汇报+断言）
7. 微调模型使用微调后的 VecNormalize（阶段5的测试）
8. 指纹/风险变量不使用最终测试期（阶段6，P1，不阻断P0验收但要在正式结果前完成）
9. 超体积参考点逐维劣于全部候选解（阶段6，P1）
10. timeout/NaN/部分结果不被标记为完成（阶段6，P1）

12. 完美预报/无预报/加噪预报三种条件能分别跑——**这一条现在的代码完全没有实现，只有完美预报一种，不在本轮范围内，作为一个新的、明确的"未做"事项写进论文限制章节，不假装做了**

### 重新生成结果

P0 全部验收通过后，按这个顺序重新生成（复用现有脚本，不需要新写）：轮作基线 → 跨季配额优化(对比1a/1b) → 边际水价值 → 算法比较 → 轮作PPO(论文二核心对比) → 迁移/微调 → 任务敏感度 → 二因素迁移风险 → 气候情景 → 对应图表。旧结果保留在 `invalidated/` 目录不删除，作为开发记录。

## 验证方式

- 每个阶段的测试用 `pytest`（项目目前没有测试框架，需要加到 `requirements.txt` 并建 `src/sim/test_*.py`、`src/rl/test_*.py` 这样和被测代码同目录的约定）。
- 阶段1完成后先用一个站点（河北中部，之前发现问题的站点）跑一次 `run_rotation_years_independent` 全部历史年份，人工核对收获日期分布，再推广到全部5站点。
- 阶段2-5完成后，先用小预算（几千步）冒烟测试 RL 训练能跑通、断言不报错，再上正式训练预算。
- 全部 P0 验收测试跑一遍绿了，再重新触发正式训练和结果生成。
